# Кейс 01 · BY VIO — запись к бьюти-мастеру в Telegram

**Формат:** демонстрационный проект для фриланс-портфолио.

**Роль:** разработка сценариев, логики записи, базы данных, кабинета мастера, тестов и конфигурации размещения.

**Технологии:** Python 3.14, aiogram 3, SQLite, Docker, GitHub Actions.

[Исходники](https://github.com/Deshead/by-vio-booking-bot) · [Попробовать бота](https://t.me/vl_booking_demo_bot)

## Задача

Сделать понятную запись для салона с одним мастером: клиент самостоятельно выбирает свободное время с телефона, а мастер видит расписание и контакты в Telegram. Учесть длительность услуг и сменный график, чтобы два человека не могли записаться на пересекающиеся интервалы.

Данные примера: мастер Виолетта, салон «Ювента», маникюр, маникюр + Френч и педикюр по два часа. Рабочее время — 09:00–18:00, график 2/2, часовой пояс Новосибирска.

## Решение

Клиент проходит короткую форму: услуга, мастер, дата, время, имя и телефон. Перед сохранением бот показывает сводку. При занятии времени другим клиентом предлагает новое окно, сохраняя контактные данные текущей формы.

«Мои записи» показывает предстоящие визиты и историю карточками с перелистыванием. Перенос сохраняет исходную запись до успешного выбора нового времени. Отмена требует отдельного подтверждения. Напоминание включается по желанию клиента перед подтверждением записи.

Кабинет мастера показывает загрузку за день и неделю, карточки клиентов и выгрузку CSV. Рабочие дни без подтверждённых визитов можно закрыть и снова открыть. В рабочем режиме доступ проверяется по Telegram ID на каждом действии.

## Что делает проект надёжнее

| Ситуация | Поведение |
|---|---|
| Два клиента одновременно выбирают одно время | Проверка пересечений и сохранение выполняются одной транзакцией SQLite |
| Двойное нажатие подтверждения | Идентификатор запроса предотвращает дубль |
| Старая кнопка после переноса | Проверка версии защищает от изменения устаревшей записи |
| Новое время уже заняли | Исходный визит остаётся на месте |
| Перезапуск процесса | Подтверждённые записи сохраняются в базе |
| Telegram ограничил отправку | Фоновая задача выдерживает указанную Telegram паузу |
| Несколько посетителей смотрят портфолио | Каждый получает отдельный демо-салон и собственный кабинет |

Контакт владельца сообщения проверяется при отправке номера через Telegram. Клиент может работать только со своими записями. Демо-данные хранятся отдельно от настоящего салона. Секреты, логи, локальные базы и резервные копии исключены из публикации.

## Как показать заказчику

1. Открыть `/start` и создать «✨ Пример записей».
2. Перейти в «Мои записи», перенести один визит и отменить другой.
3. Показать историю и актуальную карточку перенесённой записи.
4. Открыть кабинет мастера, расписание на неделю и CSV.
5. Пройти новую запись до подтверждения, показать настройку напоминания.

Страница `portfolio/index.html` содержит адаптивную презентацию и иллюстративные макеты Telegram. Переключение макетов не создаёт записи. Для настоящего взаимодействия используется бот по ссылке.

## Проверка и границы

Автономные тесты проверяют клиентские сценарии через диспетчер aiogram, конфликтные записи, миграции SQLite, роли, перенос, отмену, напоминания и восстановление данных. CI выполняет тесты на Linux и Windows и собирает контейнер. Конкретные результаты запусков доступны во вкладке Actions репозитория.

Это демонстрация разработки, а не отчёт о внедрении у реального заказчика: нет вымышленных отзывов, выручки или показателей роста. Для работы при выключенном компьютере нужен размещённый сервер и постоянный том базы; инструкция находится в [DEPLOYMENT.md](DEPLOYMENT.md). GitHub Pages показывает презентацию, Railway предназначен для процесса бота.

В текущем объёме один мастер, без онлайн-оплаты и синхронизации с внешней CRM. Незавершённая форма после перезапуска начинается заново. Расширения для конкретного заказчика могут включать нескольких мастеров, прайс, оплату и интеграцию календаря.

## Короткое описание для отклика на заказ

> Разработал Telegram-бота для записи к бьюти-мастеру: свободные окна по графику 2/2, подтверждение, перенос и отмена, личные карточки визитов и кабинет мастера с экспортом расписания. База SQLite защищает от пересекающихся записей; для демонстрации каждому посетителю создаётся отдельный пример салона. Проект содержит тесты, CI и Docker-конфигурацию размещения.
