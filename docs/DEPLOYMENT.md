# Серверный запуск BY VIO

Telegram на телефоне — интерфейс. Код бота должен работать на сервере, чтобы домашний компьютер можно было выключить. В проекте подготовлены `Dockerfile`, `compose.yaml` и `railway.json`.

Размещение требует аккаунта хостинга или доступа к VPS. Токен хранится в секретных переменных сервера. Постоянный том обязателен: без него при пересоздании контейнера записи пропадут.

## Railway

1. Создайте сервис из GitHub-репозитория проекта. Используется Dockerfile в корне; конфигурация деплоя задана в `railway.json`.
2. Подключите **Volume** с путём монтирования `/data`.
3. Задайте переменные сервиса:

   ```dotenv
   BOT_TOKEN=<токен от BotFather>
   DEMO_MODE=true
   BOOKING_DB_PATH=/data/bookings.sqlite3
   BOT_PROXY_URL=direct
   PORT=8080
   ```

4. Оставьте одну реплику. Отключите Serverless / засыпание сервиса, если включено: polling и напоминания должны работать непрерывно. Публичный домен для polling не нужен. Проверка запуска — `/health` на порту `8080`.
5. **Остановите локальный бот до старта облачного экземпляра**, чтобы два процесса не читали обновления одним токеном.
6. Выполните Deploy. В журнале должны появиться подключение к Telegram и `Start polling`. Проверьте `/start` с телефона, создайте пробную запись, перезапустите сервис и проверьте «Мои записи».

В конфигурации выбран `ON_FAILURE` с 10 попытками перезапуска. Для непрерывного размещения выберите подходящий тариф и контролируйте баланс/лимиты. Это не обещание бесплатной или гарантированной круглосуточной работы.

Документация: [конфигурация сервиса](https://docs.railway.com/config-as-code/reference), [постоянные тома](https://docs.railway.com/volumes), [политики перезапуска](https://docs.railway.com/deployments/restart-policy).

## VPS с Docker Compose

На сервере должны быть установлены Docker Engine и Compose. Скопируйте исходники в отдельную папку, без Windows `.venv`.

```sh
cp .env.example .env
```

Заполните `BOT_TOKEN`. Для настоящего салона также установите `DEMO_MODE=false` и `ADMIN_IDS=<ID мастера>`. Узнать ID можно командой `/myid` до переключения.

После остановки локальной копии:

```sh
docker compose up -d --build
docker compose logs --tail=50 bot
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ: `{"status":"ok","service":"by-vio-booking"}`. Compose сохраняет данные в именованном томе `booking_data` и перезапускает контейнер по политике `unless-stopped`. На VPS включите автозапуск Docker после перезагрузки сервера. SSH-сеанс и компьютер можно закрыть.

Обновление: скопируйте исходники и повторите `docker compose up -d --build`. Остановка: `docker compose stop`. Не используйте `docker compose down -v`, если хотите сохранить записи: `-v` удаляет том.

Резервная копия баз контейнера:

```sh
docker compose exec bot python scripts/backup.py --data-dir /data --output-dir /data/backups
docker compose cp bot:/data/backups ./backups
```

Сохраняйте копии отдельно от сервера. Для восстановления остановите сервис, замените базу соответствующей копией и снова запустите. Копируются как общая база, так и папка `demo`, если используется.

## GitHub Pages

Сайт-портфолио работает отдельно от бота и не содержит токен, базу или Python-код сервера. Workflow `.github/workflows/pages.yml` загружает только `portfolio/`.

В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**. Публикация запускается после push в `main`, если изменена презентация, либо вручную через **Actions → Portfolio Pages → Run workflow**. URL будет указан в результате задачи deploy. GitHub Pages обслуживает презентацию; процесс Telegram-бота запускается в Railway.

Документация: [публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Переключение с компьютера

Записи автоматически не переезжают. Сделайте резервную копию и перенесите `bookings.sqlite3` в `/data/bookings.sqlite3`, демо-базы — в `/data/demo/`, пока серверный процесс остановлен. Затем запустите одну серверную копию. Для портфолио можно начать с пустого демо, сохранив старую локальную базу как архив.

## Если бот молчит

- `Unauthorized`: неверный или отозванный `BOT_TOKEN`.
- `Conflict` / `getUpdates`: тот же токен используется другой копией; остановите её.
- Таймаут Telegram: проверьте исходящий доступ к `api.telegram.org`. Адрес `127.0.0.1:10809` с домашнего Windows на сервере не работает.
- Ошибка SQLite: проверьте том `/data` и права записи.
- `/health` вернул `503`: начальное подключение ещё не закончено. После запуска endpoint подтверждает работу процесса, но не гарантирует доставку каждого сообщения; при проблемах сети проверяйте журнал.

Начатая, но не подтверждённая форма находится в памяти. После обновления клиент начинает её заново. Подтверждённые записи и отметки отправленных напоминаний хранятся в SQLite.
