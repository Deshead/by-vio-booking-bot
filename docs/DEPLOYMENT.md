# Серверный запуск BY VIO

Telegram на телефоне — интерфейс. Код бота должен работать на сервере, чтобы домашний компьютер можно было выключить. Основной способ размещения — VPS с Docker Compose, без привязки к пробному тарифу конкретного сервиса.

Размещение требует аккаунта хостинга или доступа к VPS. Токен хранится в секретных переменных сервера. Постоянный том обязателен: без него при пересоздании контейнера записи пропадут.

## VPS с Docker Compose

Для небольшого демонстрационного бота стартовая конфигурация — 1 vCPU, 1 ГБ RAM и от 10 ГБ диска. Нужны исходящий HTTPS-доступ к Telegram, доступ по SSH и постоянный диск. Выбирайте тариф без автоматического засыпания; проверьте итоговую стоимость с учётом IP-адреса и диска. Аренда оплачивается, пока используется сервер, без зависимости от срока пробного периода.

На сервере должны быть установлены Docker Engine и Compose. Клонируйте исходники в отдельную папку, без Windows `.venv`:

```sh
git clone https://github.com/Deshead/by-vio-booking-bot.git
cd by-vio-booking-bot
```

Только при первом запуске, если своего `.env` ещё нет:

```sh
cp .env.example .env
```

Заполните `BOT_TOKEN` и ограничьте доступ к файлу командой `chmod 600 .env`. В `.env` деморежим уже включён. Для настоящего салона установите `DEMO_MODE=false` и `ADMIN_IDS=<ID мастера>`. Узнать ID можно командой `/myid` до переключения. Домен и открытые входящие HTTP-порты боту с polling не нужны.

**Остановите локальный бот перед запуском серверного**, чтобы две копии не читали обновления одним токеном. Затем:

```sh
docker compose up -d --build
docker compose logs --tail=50 bot
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ: `{"status":"ok","service":"by-vio-booking"}`. Compose сохраняет данные в именованном томе `booking_data` и перезапускает контейнер по политике `unless-stopped`. На Linux с systemd включите автозапуск Docker после перезагрузки сервера:

```sh
sudo systemctl enable --now docker
```

Проверьте `/start` с телефона, создайте пробную запись, выполните `docker compose restart bot` и проверьте «Мои записи». Затем SSH-сеанс и домашний компьютер можно закрыть. Сервер продолжит работу, пока доступен и действует его аренда; обслуживание провайдера и сбои сети всё ещё возможны.

Обновление: скопируйте исходники и повторите `docker compose up -d --build`. Остановка: `docker compose stop`. Не используйте `docker compose down -v`, если хотите сохранить записи: `-v` удаляет том.

Резервная копия баз контейнера:

```sh
docker compose exec bot python scripts/backup.py --data-dir /data --output-dir /data/backups
docker compose cp bot:/data/backups ./backups
```

Сохраняйте копии отдельно от сервера. Для восстановления остановите сервис, замените базу соответствующей копией и снова запустите. Копируются как общая база, так и папка `demo`, если используется.

## GitHub Pages

Сайт-портфолио работает отдельно от бота и не содержит токен, базу или Python-код сервера. Workflow `.github/workflows/pages.yml` загружает только `portfolio/`.

В настройках репозитория **Settings → Pages → Source** выберите **GitHub Actions**. Публикация запускается после push в `main`, если изменена презентация, либо вручную через **Actions → Portfolio Pages → Run workflow**. URL будет указан в результате задачи deploy. GitHub Pages обслуживает презентацию; процесс Telegram-бота запускается на отдельном сервере.

Документация: [публикация Pages через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Переключение с компьютера

Записи автоматически не переезжают. Сделайте резервную копию и перенесите `bookings.sqlite3` в `/data/bookings.sqlite3`, демо-базы — в `/data/demo/`, пока серверный процесс остановлен. Затем запустите одну серверную копию. Для портфолио можно начать с пустого демо, сохранив старую локальную базу как архив.

## Если бот молчит

- `Unauthorized`: неверный или отозванный `BOT_TOKEN`.
- `Conflict` / `getUpdates`: тот же токен используется другой копией; остановите её.
- Таймаут Telegram: проверьте исходящий доступ к `api.telegram.org`. Адрес `127.0.0.1:10809` с домашнего Windows на сервере не работает.
- Ошибка SQLite: проверьте том `/data` и права записи.
- `/health` вернул `503`: начальное подключение ещё не закончено. После запуска endpoint подтверждает работу процесса, но не гарантирует доставку каждого сообщения; при проблемах сети проверяйте журнал.

Начатая, но не подтверждённая форма находится в памяти. После обновления клиент начинает её заново. Подтверждённые записи и отметки отправленных напоминаний хранятся в SQLite.
